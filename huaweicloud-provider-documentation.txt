1. PROJECT OVERVIEW
================================================================================

Goal:
  Implement a Huawei Cloud provider for Prowler (open-source cloud security
  auditing tool) following the established provider architecture patterns
  (primarily modeled after the Alibaba Cloud provider which uses a similar
  AK/SK authentication model).

Scope:
  - Provider infrastructure (provider class, models, config, exceptions)
  - Service implementations (VPC, ECS, IAM done; CTS, ELB, EVS, KMS, OBS,
    RDS, WAF pending)
  - Security checks with metadata (4 checks done; more pending)
  - Mock authentication for development
  - Web UI integration (Prowler App)
  - API backend integration (Django ProviderChoices enum)
  - Documentation (Mintlify .mdx files)
  - Unit tests

SDK Versions (all 3.1.181):
  huaweicloudsdkcore, huaweicloudsdkiam, huaweicloudsdkecs, huaweicloudsdkvpc,
  huaweicloudsdkcts, huaweicloudsdkelb, huaweicloudsdkkms, huaweicloudsdkobs,
  huaweicloudsdkrds, huaweicloudsdkwaf

2. ARCHITECTURE DECISIONS
================================================================================

2.1 Provider Pattern
  - Follows Alibaba Cloud AK/SK pattern with official Huawei Cloud SDK
    (huaweicloudsdkcore)
  - HuaweiCloudSession wraps BasicCredentials from the SDK
  - generate_regional_clients delegates to session.client(service, region)
  - Exception codes use range 7000-7999

2.2 Authentication
  - AK/SK authentication (Access Key ID + Secret Access Key)
  - Environment variable fallbacks: HUAWEICLOUD_* and HW_* prefixes
  - Mock authentication via HUAWEICLOUD_MOCK_AUTH env var
  - Mock returns static test data for Santiago region (la-south-2)
  - Mock account ID: 123456789012
  - HuaweiCloud has ONLY static credentials (no role-based auth, no OIDC,
    no STS temporary credentials) — this simplifies UI patterns significantly

2.3 Service Base Class
  - HuaweiCloudService: __init__(self, service, provider, global_service=False)
  - Auto regional_clients generation
  - __threading_call__ for parallel API calls
  - Retry logic with configurable timeouts

2.4 Check Pattern
  - CheckReportHuaweiCloud follows CheckReportAlibabaCloud pattern
  - Check classes extend Check, execute() returns list[CheckReportHuaweiCloud]
  - Metadata JSON files follow Alibaba Cloud format
  - Client pattern: simple 4-line file importing service class and Provider,
    creating module-level client instance

2.5 Root User Identification
  - Domain owner's user_id == domain_id in Huawei Cloud
  - Fixed from flawed name=="root" heuristic

2.6 MFA
  - Huawei Cloud doesn't distinguish hardware vs virtual MFA in API
  - list_user_mfa_devices returns virtual MFA devices only

2.7 UI Credential Forms
  - Follow Alibaba Cloud pattern (AK/SK input fields)
  - 3 fields: access_key_id (text), secret_access_key (password), region (text)
  - NO SelectVia component, NO needsSelector entry, NO role schema
  - credentials-update-info.tsx returns null for huaweicloud

2.8 Branding
  - Huawei badge uses #CF0A2C brand red
  - 4-petal logo shape, viewBox 0 0 256 256

9. ENVIRONMENT VARIABLES
================================================================================

  HUAWEICLOUD_ACCESS_KEY_ID     — Access Key ID
  HUAWEICLOUD_SECRET_ACCESS_KEY — Secret Access Key
  HUAWEICLOUD_REGION            — Default region (e.g., cn-north-4, la-south-2)
  HUAWEICLOUD_MOCK_AUTH         — Enable mock authentication (any value)
  HW_ACCESS_KEY_ID             — Alternative AK prefix
  HW_SECRET_ACCESS_KEY         — Alternative SK prefix
  HW_REGION                    — Alternative region prefix
